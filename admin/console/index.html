无头请求走哪个平台

不带 X-Platform 且未绑定 Key 的请求

一个请求如果没带 X-Platform 头、 也没绑定到某个 Key，就需要决定它走哪个平台。 这个开关就是那个决定。

什么时候该打开：你写了一个程序，只关心「调用成功」， 不关心是哪个平台的模型 —— 比如内部工具、批量任务。 这时打开能把负载摊到所有平台，单个平台不会被打满。
什么时候保持关闭：你用的是官方客户端 （或任何写死了模型名的工具）。各平台模型 ID 不同 （WorkBuddy 是 hy3，Loomy 是 spark-x2.6， Qoder 是 dmodel），分摊过去会 404。

平台优先级

数字越小越优先（仅「优先级」策略生效）

            接入示例 · 语音转文字（OpenAI 兼容）
            
POST /v1/audio/transcriptions，使用同一 API Key。以 multipart/form-data 上传 file，model=workbuddy-asr。response_format 可选 json（默认，返回 {"text":"识别内容"}）或 text。网关文件上限 25 MiB，不支持 language、prompt、时间戳或流式转写。无语音时成功返回空文本，不保存音频、转写内容及调用日志。沿用 Key 状态、配额准入、频率与并发限制；绑定 Key 使用绑定账号，公共 Key 使用健康账号池。上游限额仍以上游为准。

            

            

          

          

            AI 生图 · 文生图 / 图生图（OpenAI 兼容）
            
文生图使用 POST /v1/images/generations，图生图使用 POST /v1/images/edits。指定已启用且有权限的生图模型，例如 hunyuan-image-alpha。图生图支持上传一张 image 文件（最大 20 MiB），也可通过 JSON 传入 image_url 或 base64 image_data。返回格式支持 url（默认）和 b64_json；尺寸、数量和风格以上游模型能力为准，暂不支持 mask、流式或多图输入。调用沿用 Key 限额、模型分组、账号绑定及并发保护，成功后记录真实积分用量。

            

          

          

            AI 生视频 · 异步任务（OpenAI 兼容）
            
创建任务 POST /v1/videos，轮询 GET /v1/videos/{id}，下载 GET /v1/videos/{id}/content。指定已启用的视频模型，例如 kling-video-v3、minimax-video-h3。支持 prompt、input_reference（参考图，HTTPS 或 data URL，也可 multipart 上传）、seconds、size（如 1280x720，按短边映射到上游档位）、aspect_ratio、audio。创建只到「上游已入队」就返回 queued，生成通常需要 1~5 分钟，请轮询而不是阻塞等待。按上游返回的 usage.credit 实际积分记账，不是文本倍率；超时或 5xx 不会自动重发，避免重复扣费。
